    简介

    Jev 是 TypeSafe 的旗舰判断模型，也是首个 System One 模型。传入 state 和类型化问题，直接返回代码可用的结构化答案，不生成文字。

    非官方中文翻译 · 内容以 英文原文 ↗ 为准 · 同步于 2026-10-15

    大语言模型（LLMs）被设计为输出供人类阅读的文本。当你需要模型做出代码可直接消费的判断时，便会产生错配：你不得不把一个文本生成系统强行变成输出结构化决策的工具，再把结果解析回代码可以依赖的形式。

    Jev 是 TypeSafe 的旗舰模型，也是首个 System One 模型。System One 模型被构建用于做出软件可直接使用的快速、结构化决策。Jev 会针对 state 评估类型化的 question，并直接返回结构化结果。没有文本生成，也没有解析。你得到的是类型化后的值与概率分布，代码可以据此进行分支、排序与路由。部分 题型还会返回 置信度（confidence），代码可借此决定是否以及如何对答案采取行动。每个 题型的页面都会列出其答案所包含的内容。

    TypeSafe primitives

    TypeSafe 提供了一组 AI primitives。与软件 primitives 类似，我们的 AI primitives 具有模块化、可组合、结构化、可靠和快速的特点。每种 primitive 询问不同类型的 question，并返回不同类型的答案。

    问题类型 目标 返回值
    Choice（选择题） 从列表中选出一个选项 choice、probabilities、confidence
    Score（打分题） 按评分标准对 state 打分 score、probabilities、confidence
    Noul（是非题） 该陈述是否为真？ noul（0–1）

    任意组合的 question 类型都可以在同一次 API 调用中提交。每个 question 都会针对同一份 state 并行且独立地一次性完成评估。增减 question 几乎不会影响响应时间。每个 question 都独立进行评估，因此增加 question 不会产生 context-rot。

    用代码组合原子化的问题

    System One 模型在每个 question 只询问一个具体、边界明确的事情时效果最佳。可以把每个 question 视为一次直觉式的判定：即一个高度专业的人在具备合适上下文的情况下几秒钟内就能做出的那种判断。

    如果你想询问的 question 需要长篇推理，或权衡多个相互独立的因素，那就把它拆开。把每个因素作为一个独立的 question 提出，然后在代码中用逻辑把结果组合起来。这样既能让每次评估保持可靠，又能让你完全掌控各维度的权重。

    例如，不要问"给这个创业路演打分"，而是分别就市场规模、技术可行性、差异化程度进行询问。然后用你自己的公式把分数组合起来。当优先级变化时，改动代码里的一个系数即可，而不是去改写 prompt。
