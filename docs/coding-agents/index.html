    Jev 与编程智能体

    在编程智能体里，Jev 负责结构化判断而不是写代码。本页说明 Jev 适合做什么、不适合做什么，以及怎样接到 agent 工作流。

    非官方中文翻译 · 内容以 英文原文 ↗ 为准 · 同步于 2026-10-15

    如果你在寻找一个可以接入编程智能体的模型时发现了 TypeSafe，那么从这里开始。Jev 不是 Claude Code、Cursor、opencode、Copilot、Muse Spark、Grok Bot 或类似工具背后的大语言模型（LLM）的直接替代品。相反，你可以照常使用你的编程智能体来编写调用 Jev 进行决策的代码。

    Jev 不是聊天或代码补全 LLM

    Jev 是一个 System One 模型。它不生成文本、不写代码，也不进行对话。它接收一个 state（上下文状态） 和一组类型化的 questions（问题），并返回你的代码可以直接使用的结构化答案：

    • 从一组选项（option）中返回一个 choice，并给出每个选项的概率（probability）。
    • 根据你定义的评分标准返回一个 score。
    • 对一个真/假命题返回一个 noul（0–1）。

    编程智能体依赖一个大语言模型来流式输出文本、调用工具并根据自然语言指令编辑文件。Jev 不会做任何这些事情。没有任何 model: "jev-latest" 设置能把你的编程智能体变成由 Jev 驱动的智能体（agent），因为这两个系统解决的是不同的问题。

    你可能真正想要的

    选择与你想要做的事情相对应的那一行：

    你想做的事情 做法
    让你的编程智能体更擅长编写使用 TypeSafe 的代码 安装 TypeSafe agent skill。它能让 Claude Code、Codex 以及其他智能体获得关于 Jev API、primitives 和 patterns 的完整上下文，从而为你生成正确的 TypeSafe 集成代码。
    在你正在构建的应用或智能体内部使用 Jev —— 用于路由、分类、打分、安全护栏（guardrail）或任何结构化决策 从 Quick start 开始，再阅读 How to build with TypeSafe 和 Patterns，了解 置信度分流 和 意图路由 等常见架构。
    替换或更换驱动某个编程智能体的模型 Jev 不是用于此事的工具。继续使用基于 LLM 的编程智能体，并在你的产品中需要快速、校准过的（calibrated）、结构化决策的地方单独使用 Jev。
    在编写任何代码之前先试用 Jev 打开 Playground，把一些文本粘贴为 state，再添加几个 questions。参考 Quick start 中的完整演示。

    什么时候值得使用 Jev

    尽管 Jev 不是驱动编程智能体的 LLM，但它通常恰恰是你用编程智能体构建的应用或智能体内部最合适的工具。当你的代码需要做以下事情时，就该使用 Jev：

    • 将一个请求路由到一组固定的目标之一，并知道这次路由的置信度（confidence）。
    • 按照一套评分标准（紧急程度、质量、风险）对某物打分，并根据分数走不同的分支。
    • 在采取某个动作之前，检查关于一份文档、一条消息或一条记录的某个命题是否为真。
    • 用一个在结构上就返回类型化值的调用，取代那种要求 LLM「返回 JSON」的脆弱 prompt。

    如果其中任何一项与你在构建的内容相符，那么最快的入门方式是 Quick start，然后再查阅 primitives 参考以了解题型。
