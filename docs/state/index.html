    State（上下文状态）

    Jev 的 state 是判断所依据的上下文：字符串、对象或图片。本页说明如何组织 state，以及怎样给 System One 提供足够信息。

    非官方中文翻译 · 内容以 英文原文 ↗ 为准 · 同步于 2026-10-15

    State（上下文状态） 是你让 System One 模型去评估的内容。它可以是一条客服消息、一段文本，或应用的当前 state。你把它放进 API 请求的 state 字段里，和你想问的问题一起提交。

    每一次请求会用一份 state 对一道或多道问题做评估。所有问题看到的是同一份 state，彼此独立评估。一次请求里可以同时混用 Choice（选择题）、Score（打分题） 和 Noul（是非题） 这几类题型。

    state 可以是一个简单字符串，也可以是一个结构化的 JSON 值

    最简单的 state 就是一个普通字符串：

    python
    state = "My card was charged twice."

    state 也可以是一个 JSON 对象或数组，里面可以装相关上下文、示例，以及其他能帮助模型回答对应问题的信息。可以把 state 想成你在请一专家组下判断之前会展示给他们的材料。在 Python 里，把对应的字符串、字典或列表直接传给 client.system_one(state=...) 即可。

    格式 适用场景 示例
    字符串 一条消息、文章或一段文本 "My card was charged twice."
    对象 命名字段、相关记录或应用 state {"message": "My card was charged twice.", "order_id": "A-104"}
    数组 一组有序的消息或记录 ["Hi", "My customer number is TS1337.", "My card was charged twice."]

    大多数请求建议用对象，这样 state 的各个部分都有清晰的名字，关系也一目了然。当业务场景简单、只需要一段文本时，字符串就够了。

    **提示：**state 是字符串、JSON 对象或数组。暂不支持音频和视频。Jev 的主要训练语言是英文；包括 CJK 字符在内的其他语言可以接受，但目前的准确度较低——参见 Models。

    json
    {
  "ticket": {
    "subject": "Duplicate charge",
    "messages": [
      {"from": "customer", "text": "I was charged twice for order A-104. Please refund the duplicate."},
      {"from": "support", "text": "We are checking the charges."}
    ]
  },
  "order": {
    "id": "A-104",
    "charges": [
      {"amount_usd": 49, "status": "captured"},
      {"amount_usd": 49, "status": "captured"}
    ]
  },
  "refund_policy": "Duplicate charges are eligible for a refund."
}

    整个对象就是一份 state，虽然它同时包含了一段对话、一笔订单和一条政策。当你的决策需要比较这几个部分时，就把相关信息放在同一个对象里。

    把内容与问题分开

    state 装着内容和支撑事实。Questions 定义了模型要对这些材料做哪些判断。例如，把退款申请和政策放在 state 中，再分别问客户是否申请了退款、政策是否支持这次退款。

    参见 题型总览，了解 instructions（指令）、criteria（判定标准）、题型，以及如何围绕同一份 state 提出多个问题。

    请求结构参见 API 参考，安装、类型化输入和响应处理参见 client SDKs。
