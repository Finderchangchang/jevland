    模型

    当前可用的 Jev 模型、价格、上下文长度和限流。Jev 1.14 与 1.13 都走同一 systemone 接口，用 model 字段选择版本。

    非官方中文翻译 · 内容以 英文原文 ↗ 为准 · 同步于 2026-10-15

    Jev 是 TypeSafe 的旗舰模型，也是首款 System One 模型。本页列出的所有模型都通过同一个接口提供，即 POST /v1/systemone。具体由哪个模型处理由请求中的 model 字段决定；完整的请求格式见 API 参考。

    当前模型

    Jev 1.14 Jev 1.13
    模型 ID jev-1.14.0 jev-1.13.0
    价格（每 Btok / 每 Mtok） $42 / $0.042 $42 / $0.042
    上下文长度 64k 单次请求 / 32k 单题 64k 单次请求 / 32k 单题
    输入 文本 文本

    Jev 1.14 是最新的 Jev 版本，自 2026 年 10 月 14 日起可用。

    • 价格： 按输入 token 计费。输出 token 免费。Btok 是十亿 token，Mtok 是百万 token。
    • 上下文长度： 有两个限制——单次请求上下文和单题上下文。详见 上下文长度。如需提升两者，参见 长上下文。
    • 输入： Jev 接受自然语言文本，可以是字符串、JSON 对象或文本值数组。它不接受音频或视频，需要先将其转换为文本或结构化字段，再作为 state 发送。state 支持的形态见 state（上下文状态）。

    上下文长度

    Jev 一次性读入 state，并据此并行评估每一题。请求需要同时满足两个上下文限制：

    • 单次请求上下文（per_request_context）：state 加上所有题目的总量。
    • 单题上下文（per_question_context）：state 加上任意一道题目。

    对单个请求中的题目数量没有单独限制，只要同时满足上述两个限制，任意题目数量都允许。把大量题目打包到一次请求的方法见 推测式扇出（speculative fan-out），state 增大时准确率的变化见 Jev 1.13 能力短板。

    如需提升这两个限制，参见 长上下文。

    长上下文

    长上下文默认关闭，Jev 1.14 和 Jev 1.13 均支持。开启方式是：在需要使用长上下文的请求上附带 TypeSafe-Danger-Zone-Long-Context: true 请求头。加上该请求头后，单次请求上下文和单题上下文均为 262k token。未带该请求头的请求仍按上表的默认限制执行。

    bash
    curl https://api.typesafe.ai/v1/systemone \
  -H "Authorization: Bearer $TYPESAFE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "TypeSafe-Danger-Zone-Long-Context: true" \
  -d '{
    "model": "jev-latest",
    "state": "<a long contract, transcript, or record>",
    "questions": {
      "has_termination_clause": {
        "type": "noul",
        "instructions": "Does the `state` include a clause that lets either party end the agreement early?"
      }
    }
  }'

    长上下文的每 token 价格与其他请求相同。它比默认限制下更慢、准确率也更低，因此仅在确实需要时才打开。

    限流

    限流按组织设置。你所在组织当前的限流配置可在 开发者控制台 查看。

    限流同时按每秒 token 数和每秒请求数计量。超过任一限制的请求会返回 429 Too Many Requests。我们的 客户端 SDK 默认会自动重试这类请求，每次重试间隔更长，并在响应包含 retry-after 请求头时遵循其值。直接调用 HTTP 接口的用户请参考 处理限流。

    更高的限流可在定制版和企业版套餐中提供，请联系 sales@typesafe.ai。

    别名

    别名是一个指向某个版本化模型 ID 的模型名称。它在 model 字段中的使用方式与模型 ID 一致。

    别名 指向 含义
    jev-latest jev-1.13.0 最新的稳定官方版本。客户端 SDK 的默认值，本文档示例也使用此名称。
    jev-preview jev-1.14.0 最新版本，无论是否官方。当存在预览版时，它会领先于 jev-latest。

    新版本发布时别名将随之更新，因此它的输出可能在你的代码毫无改动的情况下发生变化。每个响应的 model 字段都会给出实际作答的版本化 ID，可以据此记录每次结果由哪个模型产出。如果你针对某个版本调校过置信度阈值，请直接发送该版本的 ID 而非别名，待准备就绪后再切换到新版本。

    定制 Jev

    Jev 不会用客户数据做微调或 LoRA 适配。它通过 RLCD 训练以输出校准过的决策，且同一组权重为所有账户服务。你可以通过请求本身——而非针对每个账户的权重——来塑造它在你所在领域中的输出：

    • 把专有内容、记录和参考资料放到 state 字段中。参见 state（上下文状态）。
    • 把领域规则与边界情况编码到每个问题的 instructions 和 criteria 中。参见 如何基于 TypeSafe 构建 与 进阶：结构。
    • 把宽泛的判断拆解为原子问题，并在代码中组合结果。参见 组合打分，以及 AutoResearch 实战示例，了解如何在 Jev 的概率输出上训练下游经典模型。

    语言支持

    Jev 接受自然语言文本。英语是主要训练语言，也是当前准确率最高的语言。其他语言（含 CJK 文字）也可以处理，但效果参差不齐；在用 Jev 处理非英文工作负载前，请用你自己的内容进行测试，并在路由时密切关注 置信度。

    数据处理

    Jev 不会用客户请求或响应进行训练。数据处理协议、隐私政策以及面向企业客户的零数据保留（ZDR）详情见 法律条款。

    模型列表

    GET /v1/models 返回你账户可在 model 字段中发送的模型名称，每项包含说明和发布日期。当前它返回的是这些别名。无论是否出现在该列表中，版本化 ID（如 jev-1.14.0）都会被 model 字段接受。

    bash
    curl https://api.typesafe.ai/v1/models \
  -H "Authorization: Bearer $TYPESAFE_API_KEY"
    python
    from typesafe_sdk import TypeSafeClient

with TypeSafeClient() as client:
    for model in client.models.list().models:
        print(model.name, model.release_date, model.description)
    typescript
    import { TypeSafeClient } from "@typesafe-ai/sdk";

const client = new TypeSafeClient();
const models = await client.models.list();
for (const model of models) {
  console.log(model.name, model.release_date, model.description);
}

    • models array · 必填：每个模型或别名对应一个条目。

      • name string · 必填：模型 ID 或别名，可直接用于 model 字段。
      • description string · 必填：该模型的用途说明。
      • release_date string · 必填：该模型或别名的发布时间。

    完整方法签名见 Python 和 JavaScript SDK 参考。
